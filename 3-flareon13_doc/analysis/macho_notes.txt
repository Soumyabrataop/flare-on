BOTTOM LINE
The first slice is an animation/decoy; the second is a meaningful six-clue
checker. Crucially, its second MD5 target equals MD5(mainframe_ebcdic_ghost),
confirming the EBCDIC PDF clue belongs to this checker. Matching is unordered:
"second target" does not imply the clue must be supplied as input number 2.
No complete flag or proven ZIP password was recovered; five clue preimages
remain unknown. The README's "benign corpus payload" does not mean both
architecture slices are semantically inert.

Success path:
0x1a7ac..0x1aa6c: SHA-256-style hashing (standard rotation round structure,
initial/round constants generated from primes), then XOR each 32-byte digest
into a zeroed 32-byte accumulator. Thus the key combination is order-independent.
0x1b258: nibble-pack the ciphertext source.

0x1b530..0x1b568: standard RC4 KSA, 256-entry identity S-box,
j = (j + S[i] + key[i % 32]) & 255; swap S[i],S[j].
